## Architecture Decisions

- shadcn/ui uses the CLI default `base-nova` style, built on Base UI (`@base-ui/react`), not Radix. Icons: `lucide-react`.
- Class merging uses shadcn's `cn` package (`lib/utils.ts` re-exports it) instead of `clsx` + `tailwind-merge`.
- `shadcn` is a runtime dependency because `globals.css` imports `shadcn/tailwind.css`, along with `tw-animate-css`.
- Theme is dark only. The `globals.css` `:root` holds the ui-context palette, shadcn's variables map onto it, and there is no light or `.dark` variant block. App token utilities are documented in `ui-context.md`.
- Editor chrome components (`components/editor/*`) are controlled and stateless, with no `"use client"` directive. They take callback props, so they must be rendered from a client component that owns the sidebar and dialog state. `components/editor/editor-shell.tsx` is that component.
- `ProjectSidebar` is positioned `absolute`. Render it inside the relatively positioned canvas area below the navbar so it overlays the canvas without covering the navbar toggle.
- Route protection is default-deny in `proxy.ts` without `createRouteMatcher`, which is deprecated in `@clerk/nextjs` 7. Public routes are derived only from the Clerk sign-in/sign-up URL env vars. Pages go through `auth.protect()`. `/api/*` and `/trpc/*` get a `401` JSON response from the proxy instead, because `auth.protect()` would return `404` or a redirect. Following Clerk v7 guidance, each protected page and Route Handler also checks auth itself (`auth.protect()` / `auth()`), and future Server Actions must do the same.
- API routes: errors are `{ error: string }` via `apiError()` in `lib/api.ts`. Successes are `{ project }` / `{ projects }`, or `204` with no body for deletes. Handlers stay thin: auth, then `lib/*-input.ts` validation, then `lib/projects.ts` access check and query. Owner-only mutations call `getProjectAccess` first (`404` unknown, `403` non-owner) and also scope the write's `where` by `ownerId`.
- `cacheComponents` is on, so any `auth()` / `auth.protect()` read and the catch-all `<SignIn />` / `<SignUp />` pages sit inside `<Suspense>`. Otherwise `next build` fails on request data outside a boundary.
- Clerk appearance lives in `lib/auth-appearance.ts`. Clerk accepts `var(--…)` values for its color variables (it derives shades with `color-mix`), so the app palette is referenced directly instead of copied.
- App-specific dialog styling lives in `EditorDialog`, not in `components/ui/dialog.tsx`. `EditorDialog` disables the built-in close button and renders its own, because the built-in one is placed for the default radius and Base UI's `render` merge replaces its `data-slot`, so it can't be targeted from outside.
- Client hooks live in `hooks/` (the shadcn `@/hooks` alias) and shared domain types in `types/` (`types/project.ts`). Mock data was removed in 07. The editor reads real projects server-side.
- Database access goes only through the `prisma` singleton in `lib/prisma.ts`. Never construct `PrismaClient` elsewhere. Import the generated types from `@/app/generated/prisma/client`.
- Ownership on the client is expressed by which list a project is in: `EditorProjects.ownedProjects` vs `sharedProjects`. Only owned items get rename and delete actions. The API still enforces ownership (`403`).
- Editor pages are Server Components that load sidebar data through `lib/editor-projects.ts` behind `<Suspense>` and pass it to the client `EditorShell`. Mutations go through the project API from `useProjectActions`, followed by `router.refresh()` / navigation. There is no client-side project cache.
